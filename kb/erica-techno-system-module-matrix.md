# Erica Techno System Module Matrix

> Research note for turning the Erica Synths Techno System / Black-series
> system into practical VibeLang stdlib work. This is a behavior map and
> implementation triage, not a clone of vendor circuits, panel art, firmware, or
> manuals.

## Scope

The ticket's working rack list is Black Sequencer, Black VC Clock, Black
Wavetable VCO, Black VCO2, Black Polivoks VCF, Black VC EG, Black Quad VCA2,
Black BBD, Black Hole DSP, Bass Drum, Snare Drum, Hi-Hats, Bassline, Black
Output, and Black Mixer / Black Stereo Mixer.

Manual note: the ticket calls Black Sequencer "8-channel"; the official manual
describes 4 channels, each with CV, Gate, and Modulation outputs. The ticket
also says "Acidlab Bassline"; the official Erica page and manual name the
module "Bassline" and describe an Acidbox-inspired filter, not an Acidlab
collaboration.

Decision labels:

| Label | Meaning |
| --- | --- |
| Extend | A close stdlib building block already exists and should be extended or wrapped. |
| Rebuild | Build a new named module because hardware behavior or I/O shape is performance-defining. |
| Script | Prefer script/control utilities first; DSP is secondary or unnecessary. |
| Defer | Document, but do not build in the first wave. |

## System idioms to preserve

| Idiom | Patch behavior | VibeLang implication |
| --- | --- | --- |
| Clocked techno spine | VC Clock / Sequencer drive drums, Bassline, modulation, and resets. | Use kr clock/trigger ports and script-level pattern state; expose reset, run, shuffle, and per-track divisions. |
| Separate drum voices | Bass Drum, Snare, and Hi-Hats are individually triggerable, accentable, and CV-tweakable. | Prefer one synthdef per drum voice with trigger/accent params plus audio `out`; do not hide the kit behind a fixed drum-machine preset. |
| Acid bass as a full voice | Bassline combines oscillator, sub, BBD detune, filter, VCA, VCF/VCA envelopes, gate, accent, and external CV. | Build a dedicated `erica_bassline` voice rather than only reusing `tb303_bass` or `acid_303_classic`. |
| Patchable mono-to-stereo FX | BBD and Black Hole DSP are live-tweakable send/insert effects with CV. | Use named audio inputs with processor/effect modules; keep dry/wet, feedback, and algorithm/mode routable. |
| Mixer/output as part of the instrument | Black mixers and output/pan/headphone stages shape final performance levels. | Reuse group routing and mixer processors, but provide Erica-style mixer/output wrappers if the example patch needs a stable API. |

## Build Wave Priority

| Priority | Module(s) | Why | Suggested first implementation |
| --- | --- | --- | --- |
| 1 | Black Sequencer, Black VC Clock | Without the clock/sequencer layer the rack is just a pile of voices. | Script/control modules with kr/tr ports; keep firmware UI, SD, and MIDI exactness deferred. |
| 1 | Bass Drum, Bassline, Polivoks VCF, Black BBD, Black Hole DSP | These define the audible Techno System identity: kick, acid bass, nasty filter, analog delay, stereo FX. | Dedicated named modules using existing DSP primitives where possible. |
| 2 | Black VCO2, Black VC EG, Snare Drum, Hi-Hats | Important for full rack coverage and live modulation, but can build after the core techno path. | New multi-output VCO2 and drum voices; VC EG wrapper over cv envelope primitives. |
| 3 | Black Wavetable VCO, Black Quad VCA2, Black Output, Black Stereo Mixer | Useful for completeness and patch ergonomics; less critical than the first performance path. | Wavetable oscillator and mixer/output wrappers. |
| 4 | Black Mixer V2 | Existing routing/mixer utilities cover the practical role. | Defer unless the example patch needs exact 3-input/3-buffered-output semantics. |
