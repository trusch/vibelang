# Verbos West-Coast Module Matrix

Research scope: translate the selected Verbos west-coast rack into future
VibeLang stdlib modules while preserving named-input and named-output routing.
Existing overlap was audited under `crates/vibelang-std/stdlib/`; this document
does not implement or modify any stdlib `.vibe` or Rust file.

## Existing Stdlib Overlap

| Behavior area | Existing files | What can be reused |
|---|---|---|
| Additive / harmonic banks | `crates/vibelang-std/stdlib/instruments/spectral/spectraphon.vibe` | Reuse its explicit named outputs and unrolled additive-bank pattern. `spectraphon` already avoids large arrays by summing `sin_osc_ar(freq * k)` partials in loops and exposes multiple ports (`sine`, `sub`, `odd`, `even`). |
| Random CV | `cv/lfo/cv_lfo_random_kr.vibe`, `cv/lfo/cv_lfo_smooth_random_kr.vibe`, `cv/util/cv_sample_hold.vibe`, `cv/eurorack/cv_wogglebug.vibe`, `cv/eurorack/cv_marbles.vibe`, `cv/pitch/cv_quantizer.vibe` | Reuse `lf_noise0_ar`/`lf_noise2_ar` random sources, `a2k_kr` kr outputs, `latch_kr`/`latch_ar` sample-and-hold, and the quantizer mask-table style. |
| Touch / pressure CV | `instruments/eurorack/prss_pnt.vibe` | Reuse multi-kr-output controller shape: pressure and gate outputs per touch surface, thresholding with `in_range_kr`, pressure slew with `lag_ud_kr`. |
| Sequencer / stage CV | `cv/seq/cv_seq_step.vibe`, `cv/eurorack/cv_stages.vibe`, `instruments/eurorack/rene.vibe` | Reuse `stepper_kr`, triangular step masks, per-step params, kr gate/CV outputs, and analog-address style from `rene`. |
| Delay processors | `effects/delays/multi_tap_delay.vibe`, `processors/delays/mimeophon.vibe`, `effects/reverbs/reverb_fdn8.vibe` | Reuse named processor input style and delay building blocks. `mimeophon` is closer for voltage-controlled delay with feedback coloration; `multi_tap_delay` is closer for fixed tap fan-out but is an FX, not a patchable processor. |
| Filter banks / resonators | `processors/filters/qpas.vibe`, `effects/filters/bandpass.vibe`, `effects/filters/resonator.vibe` | Reuse named processor input style and the multi-filter mask/mix style from `qpas`; Bark needs a new fixed filter bank. |
| VCA + tone shaping | `processors/dynamics/dxg.vibe`, `processors/filters/lowpass_mono.vibe`, `processors/filters/lowpass_stereo.vibe`, `effects/filters/lowpass.vibe` | `dxg` already approximates a west-coast low-pass gate with named strike inputs; Amp & Tone needs a simpler preamp -> resonant lowpass -> VCA chain with linear and exponential CV inputs. |

## Per-Module Matrix

| Module / target stdlib name | Official behavior | Controls / params | I/O and named ports | DSP signature | Extend vs rebuild | Priority |
|---|---|---|---|---|---|---|
| Harmonic Oscillator / `verbos_harmonic_osc` | Discrete VCO with saw/square/triangle plus the first 8 harmonics as sine outputs. Each harmonic has level slider and CV input; harmonic mixer has center, width, and tilt controls. | `freq`, `amp`, `gate`, `fm_lin`, `fm_exp`, `harm1..harm8`, `harm1_cv..harm8_cv`, `center`, `width`, `tilt`, optional CV attenuverter params. | Audio outputs should include `mix`, `tri`, `saw`, `square`, and `partial1..partial8`. If CV routing needs per-partial level modulation from other voices, expose per-partial params rather than audio CV inputs first. | 8-partial additive oscillator: `sin_osc_ar(freq * k) * partial_gain_k`, summed to `mix`; gain = slider + CV + center/width/tilt window. Reuse `spectraphon`'s unrolled additive pattern, but with 8 sines instead of 64 odd/even banks. | Rebuild as new focused synthdef. Reuse only the additive implementation pattern and named-output surface from `spectraphon`. | P0 |
| Multi-Delay Processor / `verbos_mdp` | Bank of 8 voltage-controllable digital delays chained in series, roughly 10 ms to 150 ms. Provides tap outputs, envelope follower outputs for input and each delay, odd/even tap mixes, rising/falling preset mixes, manual mix, and feedback paths through reverb and +1 octave pitch shift normalled into inputs. | `delay_time`, `delay_cv`, `time_cv_amount`, `input1_gain..input3_gain`, `tap1_mix..tap8_mix`, `feedback`, `reverb_feedback`, `pitch_feedback`, `manual_mix`, `level`. | Named audio input `in` or `in1`, `in2`, `in3`; outputs `mix`, `tap1..tap8`, `odd`, `even`, `rise`, `fall`; kr outputs `env_in`, `env1..env8`. | Serial `delay_c_ar` chain with shared modulated delay time, tap extraction, tap summing, `amplitude_ar`/`a2k_kr` followers, optional `free_verb_ar` and `pitch_shift_ar` feedback normalization. | Rebuild as patchable processor. Reuse `mimeophon` for named input, local feedback, delay-time scaling, and coloration ideas; do not extend `multi_tap_delay` because it is stereo FX with fixed musical offsets and no tap/follower outputs. | P1 |
| Random Sampling / `verbos_random_sampling` | Buchla 266-style uncertainty: fluctuating randoms, quantized randoms, analog shift register, random gate, and white/pink/metallic audio noise. | `rate`, `rate_cv`, `rate_cv_amount`, `bits`, `distribution`, `clock_in`, `sample_in`, `depth_v`, `bipolar`, `noise_level`. | kr outputs `fluct_a`, `fluct_b`, `quant_a`, `quant_b`, `gate`, `asr1..asr4`; audio outputs `white`, `pink`, `metallic`. Named inputs `clock`, `sample`, optional `rate_cv`. | Fluctuating = smoothed random (`lf_noise2` or lagged noise). Quantized = S&H random snapped to bit-depth levels. Stored = four-stage shift register via cascaded latches. Audio noise = white/pink plus detuned square mixture for metallic. | Rebuild as multi-output CV/audio source. Reuse `cv_lfo_random_kr`, `cv_lfo_smooth_random_kr`, `cv_sample_hold`, `cv_quantizer`, and `cv_wogglebug` idioms, but no existing file has the complete 266-style fan-out. | P0 |
| Voltage Multistage / `verbos_multistage` | 8-stage dual-row sequencer/function generator with stage gate outputs, on/off/slide switches, voltage-controlled clock, start/stop, advance, strobe analog addressing, enable, sustain, and `ref` falling ramp. | `clock_rate`, `time`, `time_cv_amount`, `start`, `stop`, `advance`, `strobe`, `analog`, `enable`, `sustain`, `stage_a1..stage_a8`, `stage_b1..stage_b8`, `mode1..mode8`. | kr outputs `cv_a`, `cv_b`, `gate`, `ref`, `stage1_gate..stage8_gate`. Named inputs `advance`, `strobe`, `analog`, `enable`, `sustain`, `time_cv`. | `stepper_kr` for clocked stage index, triangular masks for stage selection, per-stage slide using `lag_ud_kr` or ramp interpolation, `trig1_kr` gates, falling ramp/ref from phasor-like stage phase. | Rebuild as new multi-output CV processor. Reuse `cv_stages` for step masks and `rene` for analog-address/strobe concepts; existing `cv_stages` is only 6 fixed stages and lacks dual rows, stage gates, strobe, enable, and sustain. | P1 |
| Touchplate Keyboard / `verbos_touchplate` | 32-key 1V/oct keyboard with octave select, gate, 10 ms trigger, and pressure; pressure bender; 8-key tunable keyboard with CV, pressure, and gate. | `key`, `octave`, `pressure`, `bend`, `tune1..tune8`, `tune_key`, `tune_pressure`, `threshold`, `slew`. | kr outputs `pitch`, `gate`, `trigger`, `pressure`, `bend`, `tune_cv`, `tune_gate`, `tune_pressure`, optionally per-tunable-key gate/pressure ports. | Controller synthdef: MIDI/key params mapped to V/oct, pressure slew, threshold gates, `trig1_kr` trigger pulse. No audio DSP. | Extend/rebuild from `prss_pnt` pattern. `prss_pnt` covers pressure/gate surfaces but not pitch quantization, octave select, trigger, bend, or tunable CV row. | P2 |
| Bark Filter Processor / `bark_filter` | Official tech card documents a Bark-scale fixed filter bank: lowpass at 100 Hz, ten 36 dB/oct bandpass filters at 300, 510, 770, 1.08k, 1.48k, 2k, 2.7k, 3.7k, 5.3k, 7.7k Hz, and highpass at 10.5 kHz. Each band has direct output and envelope follower; mixer has per-band sliders/CV plus center, width, and tilt. | `decay`, `center`, `width`, `tilt`, `band1..band12`, `band1_cv..band12_cv`, `odd_gain`, `even_gain`, `level`, optional follower cross-control switches. | Inputs `odd_in`, `even_in` or `in`; audio outputs `mix`, `odd`, `even`, `band1..band12`; kr outputs `follow1..follow12`, `follow_max`. If the epic's "24-band" wording is literal, expand this to `band1..band24`; otherwise treat 24 lanes as 12 audio bands + 12 follower CV outs. | Parallel fixed filter bank: LPF + 10 steep BPFs + HPF, per-band VCA, Bark-scale centers, `amplitude_ar` followers with shared decay, center/width/tilt masks. | Rebuild. `qpas` has multi-filter mixing style but is a swept stereo multi-peak filter, not fixed Bark analysis/resynthesis. Keep Bark filter infrastructure shareable with the 4ms SMR epic. | P0 |
| Amplitude & Tone Controller / `verbos_amp_tone` | Current Amp & Tone is an output voice section: input gain stage into resonant lowpass filter into VCA. Filter has cutoff CV; VCA has simultaneous linear and exponential CV. Gain and resonance can clip for tone. | `gain`, `cutoff`, `resonance`, `cutoff_cv_amount`, `amp`, `lin_cv_amount`, `exp_cv_amount`, `drive`, `level`. | Named input `in`, optional `cutoff_cv`, `lin_cv`, `exp_cv`; audio output `out`; optional kr output `env` is not on the hardware but may be useful only if kept out of fidelity path. | Preamp saturation -> resonant lowpass (`rlpf_ar`/ladder approximation) -> VCA where linear and exponential CV multiply/add into gain; soft clip at input/filter output. | Extend conceptually from `dxg` and lowpass processors but rebuild as a single-channel/stereo-capable named-input processor. `dxg` is dual low-pass gate/mixer and too different from the Amp & Tone panel. | P2 |

## Comparison And Priority

| Priority | Module | Why first | Main implementation risk |
|---|---|---|---|
| P0 | `verbos_harmonic_osc` | Core voice and explicit west-coast additive contrast; small enough to implement cleanly by adapting `spectraphon`'s additive pattern. | Per-partial CV semantics: whether CV should be separate named inputs or ordinary params driven by kr routing. |
| P0 | `verbos_random_sampling` | Core modulation source for the example patch and for driving additive partials/Bark scans. | Multi-rate fan-out: kr CV, random gates, shift-register taps, and audio noise in one synthdef need careful port declarations. |
| P0 | `bark_filter` | Signature processor and likely shared infrastructure with future fixed-filter-bank work. | Official docs say 12 filters, while the epic says 24-band; this needs clarification before fidelity scoring. |
| P1 | `verbos_multistage` | Patch needs stepped/sliding modulation and gates; existing sequencer idioms make it feasible but broader than the P0s. | Correct strobe/analog-address/enable/sustain behavior can become a mini state machine in `.vibe`. |
| P1 | `verbos_mdp` | Gives the example rack its time-domain identity after the core voice/modulation path exists. | Eight tap outputs plus envelope followers and feedback normalization may stress output count and route ergonomics. |
| P2 | `verbos_touchplate` | Useful as controller surface, but an automated example patch can use params or CV voices without live touch input. | Mapping human touch interaction into static `.vibe` params is less faithful than the DSP modules. |
| P2 | `verbos_amp_tone` | Important for a complete Verbos voice chain but easiest to approximate with existing filters/dynamics while other modules land. | Capturing discrete preamp/filter/VCA saturation character without overbuilding analog-model details. |

## Build Notes

- Keep all new modules on named inputs and named outputs. Audio outputs should use `.output(...)`; CV/follower/controller ports should use `.output_kr(...)`.
- For the Harmonic Oscillator, start with eight explicit sine partials and per-partial gain params. Add center/width/tilt as a second pass after the basic additive output and per-partial routing are stable.
- For Bark Filter Processor, implement the documented 12-filter bank unless the epic owner confirms a true 24-band target. If 24 is required, use the same structure with a denser Bark table and document the fidelity deviation from the official tech card.
- For Random Sampling, prefer one multi-output module over separate helper modules so the example patch mirrors the hardware panel: several related uncertainty outputs available simultaneously from one source.
